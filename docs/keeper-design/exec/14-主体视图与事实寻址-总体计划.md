# 14：主体视图与事实寻址 —— 总体计划清单

> 这不是单个执行规格，是**一条线的分阶段清单**。每个阶段动手前另写细规格
> （沿用 exec/NN 编号）。设计结论来自 2026-07-30 的一轮长讨论，已经用户确认，
> 不需要重新论证方向。

## 一句话目标

把「可见性」从**挂在事实上的静态标签**，翻转成**挂在主体上的视图函数**
`view(subject) → facts`；主持人、玩家、NPC 是同一种东西，只是视图不同。

## 已确认的三条决策

**① 长战役与短模组不是二选一，是同一套机制的两种退化。**
分层记忆（L1 事实账本 / L2 分段摘要 / L3 最近窗口）在短模组下 L2 天然为空、
L3 覆盖全程，行为与现在完全一致。线上/线下同理：架构一致（per-observer 视图），
只有呈现层不同（同桌时旁人看得见屏幕 → 私密内容点击展开）。
**兼顾是默认，不是妥协**；真正需要排序的只是"先验证哪一种"。

**② 只有"能被泄露的东西"才需要 id。**
全量实体化会把世界变成查表，压死守秘人的即兴空间——这是 COC 调查的命脉。
所以采用**非对称寻址**：

| 内容 | 是否要 id | 受不受 view 管辖 |
|---|---|---|
| 线索、秘密、可揭开的信息条目 | ✅ 必须有 | ✅ 受管辖，泄密可断言 |
| 场景描写、氛围、即兴内容 | ❌ 不要 | ❌ 不受管辖，**但因此不许承载秘密** |

判据一句话：**秘密必须有 id；没有 id 的东西就只能是颜色。**

**③ schema 设计看全部 5 个模组归纳共性，迁移执行先跑 1 个验证管线。**
设计与铺开是两件事。N=1 设计 schema 已经踩过一次坑（`agenda.trigger`
三枚举从《追书人》一个模组倒推，后来退回自由文本，见 exec/04）。

## 两条贯穿全程的原则

- **权限的载体是"调用前给它的 schema"，不是"调用形式"。** tool call 和结构化
  JSON 在权限上同构；受限 schema 更强，因为越权动作**无法表达**（而不是被拦住）。
  → 不需要为了做权限回到 tool calling / agent 形状。
- **控制流保持 workflow。** 主体化 ≠ 自主化。Engine 决定何时问哪个主体，
  主体只在被问到时用自己的视图做**一次**决策。v1 的自由 loop 不复活。

## P0 · LLM 调用录制回放（安全网，先做）

后面 P1/P2 是这条分支上最大的一次重构，必须先有基线。

- [ ] 拦截 LLM 客户端，把 `(messages, params, response)` 落盘为 fixture
- [ ] replay 模式：从 fixture 读，测试进程不打网络
- [ ] 挑几段真实对局录成基线（覆盖：检定发起 / 理智链式 / 场景切换 / 迷茫引导）
- [ ] 把 exec/09、10、12 里有真实样本的问题转成回放用例

**验证**：同一 fixture 重放两次结果完全一致；断网状态下测试可跑。
**边界（写清楚免得高估）**：只保证"给定模型输出，代码行为不变"，
**不保证**"新 prompt 生成的内容更好"。它是代码的回归网，不是质量的评测器。

## P1 · 地基：事实寻址 + 元层切分

- [ ] **P1.1 归纳（读全部 5 个模组）**：确定"一条可泄露信息条目"的边界共性，
      产出 schema 草案 + 每模组预计条目数。**不要从单个模组倒推**
- [ ] **P1.2 schema 落地**：信息条目成为一等公民（id / 文本 / 所属节点 /
      揭开条件）；同时把**元层**字段显式标记
      （`kp_truth` `endings` `agenda` `core_clue_paths` `on_failure` `kp_notes`
      = meta；`public_text` / 节点描写 / NPC 公开身份 = diegetic）
- [ ] **P1.3 迁移**：先 1 个模组跑通全链路验证管线，通过后再批量其余 4 个
- [ ] **P1.4 校验扩展** `validate_module.py`：秘密必须有 id；元层字段不得出现在
      任何 diegetic 渲染路径里；引用闭合照旧

**验证**：5 个模组全过校验；keeper 真实冒烟跑通；P0 的回放用例不变红。

## P2 · 主体与权限（今天这个抽象的最小落地）

- [ ] `Subject` + `capabilities` 静态声明
- [ ] 按 capabilities 构造 DecisionSchema（KP = 全权，与现 `KeeperDecision` 等价）
- [ ] `turn_executor` 执行前校验 `intent ∈ capabilities`（纵深防御，schema 已限制过一次）
- [ ] `build_context(subject)`：上下文构造器按主体过滤（KP 传全集 = 与现状等价）
- [ ] 把 `agent.py` 里"运行时"与"KP 主体"的职责拆开（`turn_executor` 拆分 +
      L1-L5 那次整理已经走了两步，这里走完）

**验证**：KP 路径行为与 P0 基线**逐字一致**（重构不改行为，这是本阶段的核心断言）；
另构造一个受限 subject，断言它拿不到元层字段。

## P3 · 第一个语义守门人：泄密不变量

- [ ] 叙事生成时声明引用了哪些 fact id
- [ ] 断言引用集合 ⊆ `view(S)`
- [ ] 逐条判断 `prose_discipline.py` 里哪些事后正则可以退役（从"事后砍"变成
      "生成时就拿不到"），**不能退役的要说明为什么**

**验证**：变异检验——故意让一条未揭开的 fact 进入叙事，测试必须变红。

> 这是整个系统里语义轴上的第一个守门人。做完之后"泄密"从
> 不可验证的散文纪律问题，变成一条能变红的不变量。

## P4 · 分层记忆（长战役；短模组零影响）

- [ ] **L1 事实账本**：代码记账，谁 / 何时 / 通过什么手段 得到哪条 fact id
      （不靠 LLM 自觉写）
- [ ] `keeper_state` 上 schema（跟 L1 一起做，终结无 schema JSON blob）
- [ ] **L2 分段摘要**：session 边界 / 场景切换触发，**离线生成**，不在玩家等待路径上
- [ ] **L3 窗口**：沿用现有 `_HISTORY_LIMIT`；同时修掉 docstring 与实现的矛盾
      （现在写"重放完整历史"，实际是最近 200 条，超出静默丢开头）
- [ ] **上集回顾**：跨 session 重入时用 L1+L2 生成

**验证**：短模组下 L2 为空、行为与现在一致（**退化证明**）；
合成一局 300+ 事件的对局，断言第 3 轮的线索在第 200 轮仍可用。

## P5 · 多人 per-observer（线上/线下同构）

- [ ] 投递通道：`manager.broadcast` → per-observer fanout
- [ ] 公共叙事一次 + **仅当某人私有增量非空时**才追加私有渲染（控成本）
- [ ] **聚合窗口取代硬拒**：`ACTION_IN_PROGRESS` 改为收集窗口（真人 KP 同时听
      四个人再回应一次；汇总必须发生在裁决之前）
- [ ] 聚光灯：导演层从"静默了多久"扩成"谁多久没被点到"
- [ ] `CheckRequest.player` 从昵称字符串改 id（同 `current_node_id` 的修法）
- [ ] 线下同桌的呈现差异：私密内容点击展开（**UI 层，不改架构**）

## P6 · NPC 主体

P2 + P3 的自然产物：`view(NPC) = 虚构内它有权知道的 − 元层`。
注意 NPC 知道的**常常超过玩家**（教徒知道教团），缺的是元层不是信息量。
必须懒调用（被搭话/相关时才跑），否则延迟失控。

## 🔴 阶段台账 —— 真人实测出问题时怎么定位到阶段

这条线要连做 7 个阶段，中间用户会启动服务真人测。**每个阶段必须留下可回溯的锚点**：

| 纪律 | 做法 |
|---|---|
| 一个阶段 = 一个 commit | 不把两个阶段揉进一次提交 |
| 一个阶段 = 一个 tag | `git tag exec14-pN`，`git diff exec14-pN..exec14-pN+1` 立刻能看这阶段动了什么 |
| 一个阶段 = 一行台账 | 下表每完成一阶段追加一行，不回头补 |
| 每阶段收尾必跑磁带回放 | `pytest tests/test_keeper_replay.py`，行为变了当场知道 |

### 出问题时的定位顺序

1. **先分层**：症状属于叙事 / 裁决 / 可见性 / 记忆 / 前端 哪一层 → 查台账里哪个阶段碰过这层
2. **再回放**：在嫌疑阶段的 tag 上 `git stash` + checkout，跑同一条磁带用例，找**第一个行为变化的阶段**
3. **分清是代码还是模型**：磁带回放红 = 代码行为变了；磁带 drift 报告 = prompt 组装变了；两者都没红但真人测有问题 = **模型输出本身的波动**，不是回归（这条最容易误判成 bug）
4. 定位后按老规矩记进对应的 `NN-真人实测问题清单-*.md`
