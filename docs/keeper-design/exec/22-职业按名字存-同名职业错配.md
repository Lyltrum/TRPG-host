# 22（待修）职业按名字存 —— 同名职业导致校验错配

> 2026-08-01 做 AI 玩家第二层（exec/21）时，**被生成器的自检抓出来的既有
> bug**，不是 AI 玩家引入的。范围超出那一层，单独记档不擅自扩大改动。

## 症状

AI 角色卡生成器自检报：

```
CREDIT_OUT_OF_RANGE@skills.credit-rating: 信用评级 20 不在职业 律师 的区间 [30, 80] 内
```

而生成时用的那个"律师"，信用区间明明是 `[20, 80]`——**信用值就是取的它的下限**。

## 根因：职业表里有同名不同项的职业

| 职业名 | 变体 | 差异 |
|---|---|---|
| 律师 | id 71 / 221 | 信用 `[30,80]` vs `[20,80]` |
| 私家侦探 | id 90 / 218 | 信用 `[9,30]` vs `[9,40]`；**技能点公式也不同**（`EDU*2+MAX(STR,DEX)*2` vs `EDU*2+MAX(APP,DEX)*2`） |
| 工匠 | id 26 / 212 | 信用 + **公式不同**（`EDU*2+DEX*2` vs `EDU*2+MAX(STR,DEX)*2`） |
| 艺术家 | id 12 / 207 | 信用不同 |
| 艺人 | id 51 / 215 | 信用 + 公式不同 |
| 科学家 | id 100 / 225 | 信用不同 |

**6 组、12 项。** 而 `Character.occupation` 存的是**职业名字符串**
（模型注释里写明了"存的是名字不是 id"），`validate_character` →
`find_occupation_by_name` 按名字查回**第一个**匹配。

于是：手里是哪个变体的信息，在落库那一刻就丢了。

## 🔴 这不只影响 AI 玩家

人类建卡同样中招，而且症状分两种：

1. **合法的卡被拒**：前端选了 id=221 的律师（信用 `[20,80]`），把信用设成 25，
   `complete_character` 校验时按名字查回 id=71（`[30,80]`）→ 判 `CREDIT_OUT_OF_RANGE`，
   玩家看到的是"我明明按规则填的，它说我不合法"。
2. **预算算错但不报错**（更阴）：工匠 / 私家侦探 / 艺人这三组**技能点公式不同**，
   查错变体 → 职业技能点预算算成另一个数 → 记账偏差不会报错，只是那张卡的
   点数上限悄悄变了。

## 与 exec/17 同族

**又一次"用自由文本当标识符"**：职业用名字当标识符，而名字不唯一。
技能那次的结论在这里逐字成立——`skill_id` 白名单解决了技能，职业这条还没走。

## 候选修法（按代价排）

1. **`Character.occupation_id`**（正解）：加字段 + 迁移 + 前端传 id。老数据按名字
   回填第一个匹配（回填时把歧义记进日志，别静默）。
2. **职业表去重**：把 6 组同名项改名（如"律师（诉讼）"/"律师（企业）"）。
   数据侧改动，不动 schema——但会改变前端已有选项的显示文本。
3. **只做校验入口**（已做，治标）：`validate_character_with_occupation` 让
   "调用方明确知道是哪个职业"时不再退回按名字猜。AI 玩家走的是这条。
   **它不解决落库丢信息的问题**。

## 已修（2026-08-01，选方案 1）

**后端**

- `Character.occupation_id` 新列 + 迁移 `9c67731c71e7`，老数据按名字回填。
  🔴 **回填时的歧义写进日志、不静默**——同名职业本来就是这个 bug 的根源，
  回填只能取第一个匹配，那正是要消灭的猜测；至少留下痕迹好核对。
  本机实测回填 9 张、零歧义。
- `complete_character` 改成**优先按 id 查**，`occupation_id` 为空（老卡/老客户端）
  才回退按名字，行为与改动前一致。
- `validate_character_with_occupation` 加 `occupation_not_found` 参数。

**前端**（三处都在按名字 find，全部改成优先用 id）

- 保存 payload 带 `occupationId`（向导在预览步骤本来就拿着它，只是没往下传）；
- `syncCurrentStateToBackend` 同上——它是第二条保存路径，漏一条就等于没改；
- `character-view.ts` / `useWizardHydration.ts` 读回时优先用 id，回退按名字。

### 🔴 修的过程中自己踩的一个坑

`validate_character_with_occupation` 第一版把 `occupation_not_found` 写成
`occupation is None`——但**"没选职业"（合法，COC7 允许无职业角色）与"选了但
查不到"（非法）是两件事**。所有未选职业的卡当场被误判成 `OCCUPATION_NOT_FOUND`，
三条既有用例转红才发现。已加参数区分，并留了一条用例钉住这个区别。
