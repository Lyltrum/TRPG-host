## 起因

前两轮真人实测(科比特先生×2、神秘渡轮×1)修的几处叙事纪律 bug,按"是否结构性泛化"分两类:

- **结构性修复(天然覆盖所有模组)**:60s 请求超时、开场仪式改走 LLM 叙事而非原文粘贴、story 页面只展示 `player_intro`。改的是代码路径,跟具体模组内容无关。
- **样本驱动的模式匹配(泛化边界不可知)**:技能同义词字典(`观察/闪躲/侦查`→`侦察/闪避`)、机制播报泄露正则、伪造检定记账泄露正则。这几条是"见一个具体失败样本→补一条规则堵住它",本质是打地鼠——换个模组、模型换个措辞,现有规则大概率堵不住。

已核实:`trpg-backend/app/core/keeper/tools.py:251` 的 `roll_check` 工具,`skill_name` 参数在 schema 层是自由文本 `str`,没有 enum/校验约束,LLM 想传什么词都行——这是同义词字典会持续缺条目的根因。

## 待办 1:技能名解析改模糊匹配

- **现状**:`_resolve_skill_target`(`tools.py:162`)精确匹配 + 人工维护的 `_SKILL_SYNONYMS` 字典 + 复合名后缀匹配。
- **方向**:对规范技能表做模糊匹配(编辑距离或类似方法),而不是维护一份只覆盖"已观测到的说法"的同义词表。目标是让模型编出的任何变体都能自动命中,不需要真人测试先撞见才能补。
- **风险/待想清楚**:模糊匹配阈值怎么定,避免把两个不同技能匹配混(如"侦查"vs"侦探"、误伤属性名)。

## 待办 2:排查伪造检定记账泄露的根源 —— ✅ 已确认并修复(2026-07-30)

- **现状(修复前)**:`prose_discipline.py` 新增了 `_FAKE_STAT_LOG_LEAK` 正则,事后从叙事正文里砍掉形如 `[理智] xxx → 损失 2,当前 San 52` 的伪造记账句(真人实测 10-#5,数据库核实这类数值从未真实发生过)。
- **根因已确认**:`agent.py::_load_room_memory` 把 `keeper.check`/`keeper.san`/`keeper.hp` 三类历史事件格式化成 `[检定] 阿福 侦察：30/70 → 成功`、`[理智] xxx：损失 N，当前 San N`、`[生命] xxx：N（原因），当前 HP N` 这种方括号"记账行",拼进 `situation`(`format_turn_input` 的"游戏历史"块),这段文本会被裁决 LLM **和**叙事 LLM(temperature 0.8,自由写作)同时看到——叙事阶段照猫画虎模仿这个可逐字复刻的模板,编出格式神似但数值全假的记账句。
- **修复**:把这三类事件的历史行渲染从方括号记账格式改成普通叙述句(不带任何方括号/特殊标记的自然语言),如"阿福进行了一次侦察检定，掷出30，目标70，结果成功。"——裁决 LLM 依然能从自然语言里读懂"末尾是否有未叙述的检定结果"(裁决规则7 的措辞已同步去掉对字面 `[检定]/[理智]` 标签的引用,改成描述性说法),但不再存在一个"看起来像系统记录、可以被逐字模仿"的模板。`prose_discipline.py` 的 `_FAKE_STAT_LOG_LEAK` 正则保留作为兜底安全网(不影响,只是预期不再触发)。
- **验证**:`tests/test_keeper_agent.py::test_load_room_memory_replays_events_in_order` 更新断言;`pytest`(305 全绿)、`ruff check`/`ruff format --check`/`ty check` 均过。改动落点仅 `agent.py::_load_room_memory` 三个 `lines.append` + `prompts.py` 裁决规则7 一处措辞,未碰协议/DTO/SDK/前端。
