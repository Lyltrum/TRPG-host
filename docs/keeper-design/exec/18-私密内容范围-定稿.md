# 18：私密内容范围 —— 定稿（exec/14 P5.2 的输入）

> 2026-07-31 与用户逐条裁决的结果。范围之外的一律不做，需要时另开。

## 一句话模型

> **COC 里绝大多数私密性的根源只有一个：你不在场，所以你不知道。**

## 🔴 这套设计成立的关键支撑：讨论区

用户裁决①时点出的：分头探索不会把人晾着，因为**玩家之间另有一条 KP 看不见的
讨论区**。

| 通道 | 谁能看 | 作用 |
|---|---|---|
| 主持人频道 | 按**位置**分发 | 你不在场，就不知道 |
| **讨论区** | 玩家之间，**KP 看不见** | 玩家自己补齐信息 |

所以 A 可以在讨论区告诉 B 他看到了什么，**而 KP 不知道 B 已经知道了**——这比
"KP 全知全能地管理每个人知道什么"更接近真人桌（真人 KP 也听不全玩家之间的
小声交流）。这同时印证了 issue #107 那条决策（AI 只消费 `action.submit`/
`dm.ask`，**不读聊天表**）是对的。

## 裁决结果

| # | 场景 | 裁决 | 判定方 |
|---|---|---|---|
| ① | **分头探索**（不同地点看不到彼此） | ✅ **做** | 代码（per-player 位置） |

| ⑦ | 检定过程与结果（谁在掷、掷了多少） | ✅ **保持公开** | —— |

### ⑥ 的一个澄清（用户提出的疑问，值得留档）

> "如果 AI 主持人不知道的话，那不就有信息差了吗？主持人就无法很好地主持了。"

**恰恰相反：主持人永远看得见。** `visibility="private"` 的私密是**玩家↔玩家**，
不是玩家↔KP：

```
A：我趁他不注意摸他口袋
  → KP 看得见，正常裁定（掷手法检定）
  → 结果只回给 A
  → B 不知道自己被摸了
```

**信息差是 B 的，不是 KP 的。** KP 不知道就没法主持——设计上从来不是那样。

### ⑤ 不做的理由

现有 5 个模组都没有这类数据，做了也是空跑。等真有模组需要时另开。

### ④ 不做的理由

它便宜（`KeeperDecision` 加 `private_notes: [{player, text}]`），但**又回到靠模型
自觉**，且"这句话该不该私聊"**没有验证器**——与 exec/17 批评的技能名问题同族。
用户 2026-07-31 裁决**不做**。以后真需要时另开，届时要先想清楚验证器。

## 落地要点

### 共用的地基：per-player 位置

①②⑥ 共用同一套投递机制（per-observer 叙事）。其中 **①是唯一需要改状态模型的**：

- **现状**：「当前场景」是 `keeper_state` 里的**房间级**单个字段
- **要变成**：per-player 位置
- **连带影响**：裁决分组、检定护栏（按谁的场景过滤）、账本渲染（各看各的）

做完 ① 之后，⑥ 接近白送（多一个"这次别广播原话"的开关，协议槽位已铺好），
② 是 ① 的变体（"在场但不可见"，共用 per-player 状态位）。

### 分组裁决的方式 —— 已定：**一次裁决全局，只叙事分开**

裁决器**本来就是全知的守秘人**（视图取全集），让它一次看清全局是自然的；
私密只发生在**输出侧**。延迟 = 1 次裁决 + N 组叙事。

否掉的两个：
- *每组各跑完整裁决*：两组并发会读到**同一份旧状态**——正是行动锁要防的事——
  必须串行，延迟翻倍，换来的"更真"并不存在（守秘人本就同时知道两边）。
- *不支持同时分头*：实现最简单，但玩家有等待感。

### ⑨ 队友角色卡：方向相反的一条

不是收紧可见性，是**放开**。现状只有「读回自己的角色卡」
（`GET /rooms/{roomId}/characters/{characterId}`），需要新增房间级列表端点
（或扩 `RoomPlayerRead`）+ SDK + 前端面板。与 ①②⑥ 无依赖，可独立做。

## 线下同桌的影响（用户提出，已纳入判断）

同一张桌子上"私密"的物理前提部分不成立（旁人看得见屏幕）：

| | 线下是否还成立 |
|---|---|
| ① 分头探索 | ✅ 完全成立（你人在书房就听不见地窖） |
| ② 潜行 | ✅ 成立 |
| ⑥ 玩家私密行动 | ❌ **基本不成立**（旁人看得见你打字）——线上功能，线下靠自觉 |
| ④ 递条子 | ⚠️ 打折，需要"点击展开"交互 |

**结论：①② 是线上线下都成立的，⑥ 只在线上有实效。** 这不影响做不做（线上是
主要形态），但影响以后线下模式的呈现设计。
