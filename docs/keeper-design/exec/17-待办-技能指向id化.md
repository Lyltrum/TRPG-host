## 关于「没有工具调用」这个心结

**tool calling 不解决这个问题。** tool call 的参数也是模型写的字符串
（`{"skill": "侦查"}`），照样能写错。真正解决的是 **enum / 白名单**，而 enum 在
两种形式里是同构的：

```
tool schema:        "skill": {"enum": ["spot-hidden", ...]}
structured output:  skill_id: Literal["spot-hidden", ...]
```

**又一次印证 exec/14 的贯穿原则：约束的载体是 schema，不是调用形式。**

## 规模是可控的

不是 229 个职业——**是 92 个技能**，封闭集合，随规则版本变、不随模组变，
且每个已有 id（`spot-hidden`、`fighting-brawl`）。让模型从 92 个 id 里选，
不是覆盖无穷的自然语言。职业数量与检定分派无关。

### ⚠️ 如实记：这不是"硬失败"

DeepSeek 走的是 **JSON mode**，不是带 schema 的 structured output，所以
`enum` **约束不到生成**——只能 prompt 给表 + 代码校验。模型仍写中文名时，
代码走**显式回退**（`_resolve_skill_target` 本来就同时认 id 和名字）并打
`keeper_skill_id_fallback` warning。

选回退而不是硬失败的理由：一刀切拒绝会在真人局里表现为"检定大面积消失"，
而那正是这条线要治的病。warning 可以统计守规率，**据此再决定要不要收紧**。
"不静默"的意思是有日志可查，不是"假装没发生"。

### (A) 模组数据组装期归一 ✅（2026-07-31）

**动手前重新统计了一遍，分布与立项时的判断不同**（43 条 / 21 种写法）：

| 类别 | 条数 | 真正的问题 |
|---|---|---|
| COC6 遗留属性检定（灵感 7、知识 4） | **11** | COC7 **没有这两个技能**（Idea/Know → INT×5 / EDU×5）。同义词表救不了 |
| 真·同义词（闪躲/观察/攀登/信用…） | 15 | 别名表能救 |
| 括号与分隔符不一致 | 7 | 复合名规范化 |
| 理智检定写进了 checks[] | 6 | 该走 `san_checks` |
| 多选检定 | 3 | schema 缺表达 |
| 组合属性 STR+DEX | 1 | 同上 |

立项时判断"最大缺口是多选检定"——**实际不是**，多选只有 3 条，最大的一块是
11 条 COC6 遗留。真正的 schema 缺口只有 4 条，其余是机械转换。

**落地形态**：`ModuleCheck` 长出 `skill_ids: list[str]` + `kind: skill|san`，
`skill` 语义收窄为**展示名**（渲染进 KP 剧本给模型读）。

- 多个 id = **任一命中即可**，多选检定点与组合属性共用这一个字段——不值得
  为 1 条 STR+DEX 单开一类 schema；
- `kind="san"` 的检定点不指向技能，不参与护栏白名单；
- `check_skills` 从"只报错"改成**进 ok、阻断产出**：脏数据再也进不了
  structured.json。

**运行时**：`check_guard` 与账本 reveals 匹配都改成 **id vs id 的集合比较**，
`_norm_skill` / `match_key` 从护栏彻底删除——两侧都是 id 之后，运行时一个
字符串匹配都不剩。这才是 exec/12 #32 的根治（当时的修法是让两边共用一张
运行时同义词表，方向错了）。

**5 个模组重跑结果**：162 个检定点全部归一，校验错误 **0**（含 6 个理智
检定点、4 个多选检定点）。原文件覆盖前已备份（不在 git 里）。

**顺带暴露的一个测试缺陷**：`test_scrub_only_deletes_never_invents` 假设
"每轮都有一次叙事 LLM 调用"。归一后 fixture 的门厅真的会发起检定，于是第二轮
走"还有待掷检定"的早返回、只回一句代码固定文案——那句话压根不是叙事产物，
拿去跟录音比对是错的。已改成只比对真正经过 LLM 的轮次。

### 剩下没做的

`SKILL_ALIASES` 这张表本身还在（组装期用）。它**不是**打地鼠——输入是固定的
5 个模组文件，一次性离线转换，转换完模组里存的就是 id。打地鼠之所以是打地鼠，
是因为运行时面对的输入无穷无尽；组装期不是。新模组进来时若出现表外写法，
`check_skills` 会**阻断**并指名是哪个节点的哪一条，人补一行别名即可。
