## 关于「没有工具调用」这个心结

**tool calling 不解决这个问题。** tool call 的参数也是模型写的字符串
（`{"skill": "侦查"}`），照样能写错。真正解决的是 **enum / 白名单**，而 enum 在
两种形式里是同构的：

```
tool schema:        "skill": {"enum": ["spot-hidden", ...]}
structured output:  skill_id: Literal["spot-hidden", ...]
```

**又一次印证 exec/14 的贯穿原则：约束的载体是 schema，不是调用形式。**

## 规模是可控的

不是 229 个职业——**是 92 个技能**，封闭集合，随规则版本变、不随模组变，
且每个已有 id（`spot-hidden`、`fighting-brawl`）。让模型从 92 个 id 里选，
不是覆盖无穷的自然语言。职业数量与检定分派无关。

### ⚠️ 如实记：这不是"硬失败"

DeepSeek 走的是 **JSON mode**，不是带 schema 的 structured output，所以
`enum` **约束不到生成**——只能 prompt 给表 + 代码校验。模型仍写中文名时，
代码走**显式回退**（`_resolve_skill_target` 本来就同时认 id 和名字）并打
`keeper_skill_id_fallback` warning。

选回退而不是硬失败的理由：一刀切拒绝会在真人局里表现为"检定大面积消失"，
而那正是这条线要治的病。warning 可以统计守规率，**据此再决定要不要收紧**。
"不静默"的意思是有日志可查，不是"假装没发生"。
